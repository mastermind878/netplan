# NetPlan — планирование IPv4-сетей

NetPlan — небольшой сервис на FastAPI для студентов и начинающих системных
администраторов. Он рассчитывает параметры IPv4-подсети, проверяет принадлежность
адреса, разбивает сеть на равные подсети и обнаруживает пересечение сетей.

Пример задачи: для учебного класса выделена сеть `192.168.1.0/24`.
Нужно разделить её на четыре сети. Запрос `/networks/split` с `new_prefix=26`
возвращает четыре подсети по 64 адреса, в каждой по 62 обычных адреса узлов.

Не нужны база данных, Docker, платные сервисы или API-ключи. Вычисления локальные:
приложение не подключается к указанным IP-адресам и не выполняет сканирование.

## Установка и запуск

Требуются Python **3.12** и Git. Команды выполняются из корня проекта.
Клонирование публичного репозитория:

```text
git clone https://github.com/mastermind878/netplan.git
cd netplan
```

Также можно распаковать архив исходников. Для дальнейшей работы с Git рекомендуется клонирование репозитория.

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt -c constraints.txt
.\.venv\Scripts\python.exe -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Активация окружения не требуется: команды обращаются непосредственно к его Python.
Такой способ не требует менять ExecutionPolicy в PowerShell.

### Linux / macOS

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt -c constraints.txt
.venv/bin/python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Для установки только приложения замените `requirements-dev.txt` на `requirements.txt`.
`constraints.txt` фиксирует версии прямых и транзитивных зависимостей проверенного окружения.

Откройте [Swagger UI](http://127.0.0.1:8000/docs): выберите маршрут,
нажмите **Try it out**, заполните параметры и нажмите **Execute**.
Обычный запуск выше намеренно без `--reload`. Для разработки можно добавить
`--reload`. Остановка сервера: `Ctrl+C`.

## Маршруты

Все маршруты используют GET и не изменяют состояние.

| Маршрут | Параметры | Назначение |
|---|---|---|
| `/` | — | Название сервиса и ссылка на документацию |
| `/health` | — | Проверка работоспособности: `status=ok` |
| `/version` | — | Версия приложения: `1.0.0` |
| `/networks/info` | `cidr` | Маска, границы, число адресов и диапазон узлов |
| `/networks/contains` | `cidr`, `ip` | Принадлежность сети и пригодность адреса для узла |
| `/networks/split` | `cidr`, `new_prefix` | Разбиение на равные подсети |
| `/networks/compare` | `left`, `right` | Пересечение и вложенность двух сетей |

Примеры для PowerShell (сервер должен работать в другом терминале):

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/health'
Invoke-RestMethod 'http://127.0.0.1:8000/version'
Invoke-RestMethod 'http://127.0.0.1:8000/networks/info?cidr=192.168.1.42%2F24'
Invoke-RestMethod 'http://127.0.0.1:8000/networks/contains?cidr=192.168.1.0%2F24&ip=192.168.1.10'
Invoke-RestMethod 'http://127.0.0.1:8000/networks/split?cidr=192.168.1.0%2F24&new_prefix=26'
Invoke-RestMethod 'http://127.0.0.1:8000/networks/compare?left=10.0.0.0%2F24&right=10.0.0.128%2F25'
```

В Linux/macOS используйте `curl` с теми же URL в кавычках.
`%2F` — кодирование символа `/` в параметре URL.

### Правила расчётов и ошибки

- В `cidr` обязательна маска. `192.168.1.42/24` нормализуется в `192.168.1.0/24`.
- Только IPv4. IPv6 и некорректные адреса возвращают HTTP 422 с объяснением в JSON.
- Для `/0`–`/30` адрес сети и broadcast исключены из диапазона узлов.
- `/31` трактуется как point-to-point сеть с двумя адресами; `/32` — один адрес.
  Поле `broadcast` отражает верхнюю границу сети; для `/31` и `/32` оно не
  означает отдельный широковещательный адрес.
- `belongs` означает принадлежность, а `usable_as_host` дополнительно проверяет
  исключение адреса сети/broadcast для обычных подсетей. Это расчёт по маске,
  а не гарантия реальной доступности или пригодности адреса в интернете.
- Новый префикс должен быть строго больше исходного и не превышать 32.
- Число подсетей вычисляется **до** формирования списка: `2 ** (new_prefix - prefix)`.
  Превышение `MAX_SUBNETS` возвращает 422 и не выделяет огромный массив.
- Одинаковые сети считаются пересекающимися и вложенными друг в друга.

## Настройки окружения

| Переменная | По умолчанию | Допустимые значения |
|---|---|---|
| `APP_NAME` | `NetPlan` | Название в `/health`, `/` и Swagger |
| `LOG_LEVEL` | `INFO` | DEBUG, INFO, WARNING, ERROR, CRITICAL |
| `MAX_SUBNETS` | `256` | Целое число от 1 до 4096 |

Пример PowerShell (до запуска сервера):

```powershell
$env:APP_NAME = 'Network Lab'
$env:MAX_SUBNETS = '64'
$env:LOG_LEVEL = 'INFO'
.\.venv\Scripts\python.exe -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Linux/macOS:

```bash
APP_NAME='Network Lab' MAX_SUBNETS=64 LOG_LEVEL=INFO .venv/bin/python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Настройки считываются при создании приложения; после изменения нужен перезапуск.
`.env.example` — безопасный справочный файл. `.env` **не загружается автоматически**:
задавайте переменные через оболочку, как показано выше. Неверные `MAX_SUBNETS` или
`LOG_LEVEL` приводят к явной ошибке запуска с названием настройки.

## Тесты

В активированном окружении стандартная команда задания:

```text
python -m pytest -v
```

Без активации в Windows:

```powershell
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts/smoke.py
```

В Linux/macOS замените путь Python на `.venv/bin/python`.

Набор содержит 36 проверок: служебные маршруты, расчёты, нормализация,
границы `/0`, `/31`, `/32`, фильтрация неверного ввода, предел числа подсетей,
вложенность и пересечение сетей, настройки, жизненный цикл и логи.
Тесты используют `TestClient`; контекстный менеджер запускает lifespan.
`scripts/smoke.py` дополнительно запускает настоящий Uvicorn на свободном локальном
порту, проверяет HTTP-ответы и останавливает дочерний процесс даже при ошибке.

## CI и artifact

`.github/workflows/ci.yml` выполняется при каждом `push`, `pull_request` и вручную.
Последовательность: Python 3.12 → установка зависимостей → `pip check` →
`python -m pytest -v` → реальный HTTP-запуск → упаковка → загрузка artifact.

После успешных проверок появляется artifact **netplan-source**, содержащий
`netplan-source.zip`. В архив входят все отслеживаемые Git файлы, включая
`.env.example` и workflow. `.git`, окружения и настоящий `.env` туда не входят.
Срок хранения artifact — 30 дней; перед проверкой преподавателем при необходимости
повторно запустите workflow кнопкой **Run workflow**.

Откройте вкладку **Actions**, дождитесь зелёного статуса последнего
запуска для последнего коммита, откройте его и проверьте блок **Artifacts**.
Локальные успешные тесты не заменяют фактический запуск GitHub Actions.

## Логи и диагностика

Логи выводятся в терминал сервера: время, уровень, имя логгера, событие.
Есть `service_started`, `service_stopped`, а также метод, путь, HTTP-статус и
длительность каждого запроса. `INFO` — режим демонстрации логирования; при
`WARNING` обычные информационные события будут скрыты.
Значения query-параметров, тела и заголовки собственный логгер NetPlan не записывает.
Стандартный access log Uvicorn может содержать URL с параметрами; не вводите секреты
в URL. Для отключения access log используйте `--no-access-log`.

| Симптом | Проверка и решение |
|---|---|
| `No module named fastapi` | Установите зависимости тем же Python, которым запускаете сервер |
| `Could not import module app_final` | Перейдите в корень проекта, где находится `app_final.py` |
| Порт 8000 занят | Запустите с `--port 8001` и используйте этот порт в URL |
| Браузер не подключается | Посмотрите ошибки в терминале; проверьте `/health` и порт |
| Ответ 422 | Проверьте `detail`, обязательные параметры, маску и лимит подсетей |
| Ошибка MAX_SUBNETS/LOG_LEVEL при запуске | Исправьте переменную окружения и перезапустите |
| CI красный | Откройте упавший шаг в Actions; повторите его команду локально |
| Artifact отсутствует | Проверьте успешность тестов и срок хранения 30 дней |

Для сохранения логов в PowerShell добавьте `2>&1 | Tee-Object -FilePath netplan.log`
в конец команды Uvicorn. Файлы `*.log` исключены из Git.

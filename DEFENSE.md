# Сценарий защиты NetPlan

## Демонстрация на 5–7 минут

1. Объясните задачу: студент или администратор планирует IPv4-сеть,
   проверяет диапазоны адресов и избегает пересекающихся подсетей.
2. Покажите публичный GitHub, структуру файлов и `git log --oneline`.
   Коммиты отражают реальные этапы подготовки проекта, выполненные с помощью ИИ.
3. Запустите сервер командой из README без `--reload`. Покажите событие запуска.
4. Откройте `/health`, `/version` и `/docs`.
5. `/networks/info`: `192.168.1.42/24`. Получаем `192.168.1.0/24`, 256 адресов,
   254 обычных узла, маску `255.255.255.0`.
6. `/networks/split`: `192.168.1.0/24`, новый префикс 26.
   Получаем `.0/26`, `.64/26`, `.128/26`, `.192/26`.
7. `/networks/contains`: сеть `/24`, адрес `.255`.
   Он принадлежит сети, но для обычного узла не подходит: это broadcast.
8. `/networks/compare`: `10.0.0.0/24` и `10.0.0.128/25`: пересекаются,
   вторая вложена в первую.
9. Ошибка: `cidr=abc` или разделение `/0` на `/32`: HTTP 422, понятное сообщение.
10. Покажите логи запросов. Остановите сервер, задайте `MAX_SUBNETS=2`, запустите
    снова: разбиение `/24` на `/26` теперь отклоняется (нужны четыре подсети).
11. Запустите `python -m pytest -v`: 36 проверок. Покажите также `scripts/smoke.py`.
12. Откройте последний зелёный Actions run и artifact с исходниками.

## Как объяснить устройство

`create_app()` читает настройки и создаёт FastAPI. Фабрика позволяет тестам
создавать независимые приложения с разными настройками. `app = create_app()`
даёт Uvicorn точку входа `app_final:app`.

`lifespan` логирует запуск и остановку. HTTP middleware измеряет время запроса
и записывает статус. `Query` ограничивает параметры; собственные проверки
добавляют предметные правила. Для ожидаемых ошибок используется HTTPException 422.

`parse_network()` требует маску и нормализует адрес с host bits.
`describe()` вычисляет границы арифметически, без обхода всех адресов.
Для `/24` всего 2^(32-24) = 256 адресов, обычно 256-2 = 254 узла.
Для `/31` и `/32` применяются специальные правила библиотеки ipaddress.

При разбиении `/24` на `/26` добавляются два бита сети: 2^(26-24) = 4 подсети.
До генерации списка сравниваем число с лимитом. Поэтому даже вход `/0 -> /32`
не создаёт четыре миллиарда объектов.

CI работает на GitHub: checkout получает код, setup-python готовит Python,
pip устанавливает версии, pytest проверяет поведение, smoke запускает настоящий
сервер. Только после успешных шагов git archive и upload-artifact сохраняют исходники.

## Возможные вопросы

**Зачем /health отдельно от /version?** Первый проверяет ответ работающего процесса,
второй позволяет определить версию. В этом сервисе нет БД и внешних зависимостей,
поэтому health не проверяет их.

**Почему без базы данных?** Сервис выполняет чистые расчёты и не хранит сущности.
База не нужна для задачи и не является требованием.

**Почему параметры query, а не path?** Значение CIDR содержит `/`, его проще
передавать как параметр. Swagger корректно кодирует URL.

**Проверяет ли сервис, занят ли адрес?** Нет. Принадлежность сети — математическое
свойство. Сервис не отправляет пакеты, не проверяет DNS и не сканирует сеть.

**Что дают тесты сверх проверки /health?** Проверяют результаты вычислений,
обработку ошибок, настройки, защиту от больших результатов и особые сети.

**Почему один worker допустим?** Нет общего изменяемого состояния; достаточно
стандартного Uvicorn для демонстрации. Производительность отдельно не измерялась.

**Что сделано самостоятельно в проекте?** Объясните функции, тесты и решения своими
словами; проект подготовлен с помощью ИИ. Не заявляйте о разработке без помощи.
Перед сдачей выполните демонстрацию сами и разберитесь в коде.
